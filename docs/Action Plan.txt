Feature 2.2: Worker Node 1 Preparation and Provisioning
Phase 1: Hardware & Image Preparation (DoD 1 & 2)
1. System Extension Audit: The Lenovo ideacenter relies on a Realtek RTL8111/8168 PCI Express Gigabit Ethernet Controller. This NIC is typically supported by the upstream Talos kernel, but we will utilize factory.talos.dev (or the Sidero SchedMD API) to generate a v1.13.7 ISO, injecting the siderolabs/realtek-r8152 extension if dmesg flags missing firmware during early boot.
2. Network Isolation: Talos strictly expects reliable wired networking. The Intel Dual Band Wireless-AC 3165 adapter will be disabled in the Lenovo UEFI/BIOS to prevent talos-networkd from attempting to route metrics or pull images over an unstable wireless bridge.
3. Boot to Maintenance Mode: Flash the generated .iso to media. Boot the Lenovo node and allow it to initialize into Maintenance Mode.
Phase 2: OpenTofu Declarative IaC (DoD 3)
1. Provider Initialization: Configure the siderolabs/talos OpenTofu provider in the repository's infrastructure directory.
2. Machine Secrets & Config: Generate or extract the existing cluster machine secrets. Define a talos_machine_configuration_apply resource targeting IP 10.10.10.52.
3. Storage Targeting: The Lenovo node possesses a 465.8G ST500DM002-1SB10 HDD (/dev/sda). The OpenTofu Talos machine configuration patch will explicitly target /dev/sda as the installation disk to ensure the OS installs to the persistent disk rather than ephemeral memory.
4. Apply State: Execute tofu plan and tofu apply to push the declarative configuration. Talos will write to /dev/sda, reboot, and transition to a running state.
Feature 2.3: Worker Node 2 Preparation and Provisioning
Phase 1: Hardware & Image Preparation (DoD 1 & 2)
1. System Extension Audit: The Realtek RTL810xE may require explicit kernel extensions (e.g., siderolabs/realtek-r8152) if the upstream Talos kernel lacks driver support during initial boot.
2. Network Isolation: Talos requires reliable wired networking. The Intel Wireless 7260 must be disabled via the Dell UEFI/BIOS to prevent talos-networkd from attempting to route metrics across an unstable backhaul.
3. Boot to Maintenance Mode: Generate and flash the v1.13.7 Talos ISO, boot the Dell hardware, and allow it to initialize into Maintenance Mode.
Phase 2: OpenTofu Declarative IaC (DoD 3)
1. Manifest Integration: Append data "talos_machine_configuration" "worker2" and resource "talos_machine_configuration_apply" "worker2" to the existing OpenTofu state.
2. Configuration Patch: Target the 931.5G ST1000LM024 HDD at /dev/sda for the Talos installation to ensure it does not write to ephemeral loop devices. Assign the static IP 10.10.10.53 and map it to the logical interface enumerated for the Realtek NIC.
3. Apply State: Execute tofu plan and tofu apply to push the declarative machine configuration and transition the node to a running state.
Phase 3: Validation (DoD 3 & 4)
1. Validate network routing via ICMP ping to 10.10.10.53.
2. Validate cluster quorum via talosctl health --nodes 10.10.10.53 and talosctl get members.
