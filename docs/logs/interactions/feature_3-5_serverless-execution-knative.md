# Feature 3.5 Human–AI Interaction Summary: Serverless Execution (Knative)

**Date:** 2026-11-23  
**Feature:** 3.5 — Serverless Execution (Knative)  
**Related Artifacts:** [Implementation Plan](../../implementation%20plans/feature_3-5_implementation_plan.md) | [Epic Log](../epic-3.md) | [Retrospective](../../Retrospective.csv) | [Cluster Access Runbook](../../runbooks/cluster-access.md)

## 1. Collaboration Arc
Feature 3.5 was re-initiated immediately after the Feature 3.4-R bare-metal hardware consolidation and GitOps restoration, progressing from `/feature-initiation` through four gated phases to `/retrospective` with zero imperative cluster mutations. The agent audited the post-refactor cluster baseline and re-baselined the stale pre-refactor plan; the human used inline file comments to challenge rationale and lock Option A for both architectural decisions (IPAM boundary tightening and internal event-driven routing) before any manifests were modified. Execution followed a disciplined human-runs-CLI / agent-authors-Git cadence using dynamic VS Code terminal context to diagnose a bootstrap KPA webhook race, validate scale-to-zero and Argo Workflows-to-Knative routing, and close out with a new centralized day-2 operational runbook and a scheduled Feature 4.4 lifecycle upgrade.

## 2. Guardrails & Rules That Held
* **Audit-Before-Write (ABW) & Post-Refactor Re-Baselining:** Cross-checking [epic-3-refactor-hardware-and-state-consolidation.md](../epic-3-refactor-hardware-and-state-consolidation.md) against live manifests surfaced three drifts prior to execution: obsolete low-memory `worker-1` and `kube-vip` references, an IPAM overlap between `CiliumLoadBalancerIPPool` and the ER605 DHCP pool, and swapped Kourier/NGINX VIP entries in [infrastructure/networking/README.md](../../../infrastructure/networking/README.md).
* **Search-Before-Write Schema & Container Verification:** Live upstream lookups prevented two first-try deployment failures—confirming exact Cilium `v1.15` `start`/`stop` IPAM block syntax and catching that `curlimages/curl` runs Alpine BusyBox `sh` (which rejects bash-only `set -o pipefail`), allowing `/bin/sh -eu -c` to succeed on the first workflow run.
* **Strict GitOps Exclusivity:** When `helloworld-go-00001` remained stuck in `RevisionMissing` due to a missing KPA autoscaler annotation, the team avoided imperative deletion/patching and instead updated [test-ksvc.yaml](../../../infrastructure/serverless/knative/test-service/test-ksvc.yaml) to explicitly bind the KPA class and harden `securityContext`, rolling a clean new revision declaratively through ArgoCD.
* **Two-Option Rule & Inline Gate Reviews:** Presenting structured Option A/B trade-offs and halting at the Gate Check enabled rapid consensus before writing manifests.

## 3. Agent Blind Spots & Human Pushback
* **Unexplained Plan Rationale Challenged Inline:** On the re-baselined plan, the human left two inline comments questioning why `set -euo pipefail` was mandated and why the earlier dual-ingress callout had been removed, prompting the agent to tie both explicitly to Feature 3.4 retrospective history and ADR-0003/ADR-0009.
* **Missing Architectural Context Before Phase 3 Manifests:** The agent authored [knative-trigger-workflow-template.yaml](../../../infrastructure/bootstrap/argo-workflows/knative-trigger-workflow-template.yaml) and instructed triggering it via the "Argo Workflows UI" without first explaining the Step Functions-to-Lambda cross-namespace routing flow or verifying how the human accessed Argo Workflows. Human pushback ("Explain these changes more clearly... How do I get to the Argo Workflows UI?") exposed both the explanation gap and the fragility of tracking UI access commands in an external text editor.
* **HTTPS Port-Forward Protocol Quirk Not Preempted:** Initial port-forward guidance did not preempt browser TLS resets or `http://` vs. `https://` mismatches against `argo-server`'s HTTPS default, requiring an extra read-only check of deployment args to resolve `connection reset by peer`.
* **Closeout & Governance Refinements:** During `/retrospective`, the human refined the diagnostic formatting rule to explicitly mandate separate code blocks per command, requested an inline UI execution walkthrough in [cluster-access.md](../../runbooks/cluster-access.md), directed adding Feature 4.4 to both the Roadmap and root [README.md](../../../README.md), and explicitly opted out of a separate Epic 3 retrospective.

## 4. Workflow & Context Friction
* **Terminal Scrollback Clipping in Batched Diagnostics:** Combining verbose Knative controller, autoscaler, and webhook log tails with structured `kubectl get`/`describe` outputs in a single paste overflowed the VS Code terminal buffer twice, clipping the critical `revision` and `kpa` outputs and costing two extra diagnostic turns before isolating the missing `autoscaling.knative.dev/class` annotation.
* **Externalized Operational Commands:** Tracking management UI port-forwards and token extraction commands in a standalone text file outside Git slowed Phase 3 validation; moving them into [docs/runbooks/cluster-access.md](../../runbooks/cluster-access.md) established a durable, Zero-Token-in-Git operational reference.
* **Latent Version Skew Surfaced During Debugging:** Live controller logs revealed a 10-minor-version skew (`Knative v1.14.0` on `Kubernetes v1.36.1`) emitting continuous `v1 Endpoints` deprecation warnings, which the team intentionally deferred into Feature 4.4 rather than risking a mid-feature operator upgrade deadlock.

## 5. `.agents/` Evolution
* **Retrospective Action Items Codified ([docs/Retrospective.csv](../../Retrospective.csv)):** Feature 3.5 established three durable workflow standards—(1) isolating every diagnostic command in its own separate markdown code block to prevent terminal buffer clipping and simplify copy-paste (subsequently formalized in [gitops-lab-architect.md](../../../.agents/rules/gitops-lab-architect.md) under *Mandatory Validation block & Diagnostic Output Hygiene*), (2) pairing cross-layer integrations with upfront architectural flow explanations and centralized UI/API access steps in [docs/runbooks/cluster-access.md](../../runbooks/cluster-access.md), and (3) scheduling **Feature 4.4 (`Platform Lifecycle & Version Debt Remediation`)** at the end of Epic 4 to systematically address upstream version skew prior to Epic 5 hardening.
