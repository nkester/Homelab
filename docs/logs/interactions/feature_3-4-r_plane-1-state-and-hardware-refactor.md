## 1. Collaboration Arc
Feature 3.4-R executed across five gated phases—from physical hardware harvesting and ER605 DHCP reservations through iterative node-by-node OpenTofu provisioning (backed by GitLab HTTP remote state), ArgoCD GitOps restoration, and documentation closeout—rebuilding the entire Plane 1 foundation into an all-desktop, all-Gigabit cluster. Execution followed a disciplined division of labor: the human performed physical hardware work, terminal executions (`tofu`, `talosctl`, `git`), and UI actions while the agent authored Terraform/YAML manifests, ran targeted read-only `kubectl` diagnostics and live registry checks, and maintained documentation parity. When upstream surprises hit during Phase 4 (Helm resource ownership conflicts, MinIO's container registry privatization, and a MinIO Operator upgrade deadlock), strong human architectural pushback turned tactical workarounds into durable governance decisions (`ADR-0011` and Feature 4.3).

## 2. Guardrails & Rules That Held
* **Strict Command Execution Boundaries & Zero-Token-in-Git:** When the agent attempted to run `git add`/`git commit` directly, the human denied execution ("I will make git commits"), cleanly enforcing manual commit control. GitLab remote-state PATs, ESO tokens, and runner registration secrets remained strictly out-of-band (`.env` git-ignored; secrets injected manually).
* **Two-Option Rule for Strategic Trade-Offs:** Presenting Option A (interim `pgsty/minio` bridge + scheduled FOSS migration) vs. Option B (sovereign GitLab CI container builds) allowed rapid consensus without expanding Feature 3.4-R's blast radius.
* **Audit-Before-Write (ABW) & Stop-and-Check Gatekeeping:** Auditing existing ADRs, [HomeLab_Project_Roadmap.csv](../../HomeLab_Project_Roadmap.csv), [README.md](../../../README.md), and [infrastructure/bootstrap/README.md](../../../infrastructure/bootstrap/README.md) before authoring Phase 5 closeout artifacts prevented ADR numbering collisions (`ADR-0010` vs. `ADR-0011`) and documentation drift.

## 3. Agent Blind Spots & Human Pushback
* **Unverified Upstream Registry Assumption:** To bypass Docker Hub failures, the agent initially pinned [tenant.yaml](../../../infrastructure/storage/minio/tenant.yaml) to `quay.io/minio/minio` without verifying live anonymous pull access, causing a `401 UNAUTHORIZED` `ImagePullBackOff`. Human feedback forced live registry API verification, uncovering MinIO's upstream source-only archival and leading to the verified `pgsty/minio` drop-in build (applied to both `minio-tenant` and [argo-workflows/kustomization.yaml](../../../infrastructure/bootstrap/argo-workflows/kustomization.yaml)).
* **FOSS Sustainability & Technical Debt Challenge:** Rather than accepting the third-party mirror silently, the human pushed back on taking on supply-chain debt for a non-FOSS-distributed tool and evaluated sovereign GitLab Container Registry builds vs. FOSS alternatives. This directly produced [ADR-0011](../../adr/0011-minio-foss-deprecation-and-s3-migration-strategy.md) and scheduled **Feature 4.3 (FOSS S3 Object Storage Migration — SeaweedFS / Garage)** intentionally after Ingress/TLS (Feature 4.2) so wireless VLAN 10 access is established first.
* **Git History Churn vs. App-of-Apps Self-Healing:** When the MinIO Operator deadlocked on an offline image update, the agent proposed a two-commit `git mv` prune/re-provision cycle to stay strictly declarative. The human pushed back ("Why would I not just delete the application in the argocd UI and allow it to re-deploy it instead of making commits to my git repository?"), identifying a cleaner recovery path that leveraged `root-app` self-healing without polluting Git history.
* **Pre-Action State Verification:** Before deleting `minio-tenant` in the UI, the human required confirmation that no hidden defects remained in the namespace. A full read-only audit of `ExternalSecret`, Longhorn PVCs, services, and operator logs proved the controller deadlock was the sole blocker, resulting in immediate recovery upon re-creation.
* **Operational Clarity Gaps:** The human also challenged pinning exact image tags over `:latest`, surfaced the ArgoCD UI `localhost:8080` refusal (`--insecure` HTTP vs. browser HTTPS auto-upgrade), and verified the `argocd-deploy` branch merge flow prior to syncing.

## 4. Workflow & Context Friction
* **Bootstrap Ownership Collisions:** Migrating ArgoCD from unnamespaced Talos `extraManifests` (which placed pods in `default`) to OpenTofu `helm_release.argocd` in [main.tf](../../../infrastructure/bootstrap/main.tf) triggered sequential Helm adoption errors across CRDs, `ClusterRole`s, and `root-app` finalizers, costing multiple `tofu apply` retries.
* **Operator Deadlock Obscuring GitOps Convergence:** Even after Git (`argocd-deploy`) and the live `Tenant` CR reflected `pgsty/minio`, the ArgoCD UI continued displaying stale `minio/minio` and `quay.io` pod errors because the MinIO Operator blocked StatefulSet updates while health checks failed.
* **Empirical Hardware Discovery:** Bare-metal staging surfaced an unexpected `worker-1` NIC MAC address and USB-shifted SATA device paths, requiring mid-flight DHCP reservation and `terraform.tfvars` updates.

## 5. `.agents/` Evolution
* **Retrospective Entries Codified ([docs/Retrospective.csv](../../Retrospective.csv)):** Feature 3.4-R recorded five Sustain/Improve learnings—mandating upstream distribution/licensing audits before bootstrapping third-party dependencies, auditing custom operator upgrade health gates prior to in-place updates, and standardizing on ArgoCD App-of-Apps self-healing for stuck controller recovery.
* **Downstream Governance Impact:** No `.agents/` files were modified directly during Feature 3.4-R, but its lessons directly informed the upstream supply-chain checks and command-execution boundaries subsequently formalized in [feature-initiation/SKILL.md](../../../.agents/skills/feature-initiation/SKILL.md) and [gitops-lab-architect.md](../../../.agents/rules/gitops-lab-architect.md).
